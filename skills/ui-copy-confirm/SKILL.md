# UI 문구 확정 전 확인 (ui-copy-confirm)

## 왜 중요한가

placeholder 문구, 에러 메시지, 버튼 라벨은 최종 사용자가 직접 읽는 텍스트다 — 문구를 잘못 정하면
(너무 일반적이거나, 기존 화면들과 톤이 안 맞거나, 그냥 대충 지어낸 경우) 기존 문구들 옆에서 어색해
보이거나 나중에 다시 고쳐야 한다. 변경을 요청한 사람은 보통 코드만 봐서는 알 수 없는 도메인 지식
(실제 고객사명, 실제 제품 코드, 원하는 실제 톤)을 갖고 있다. 미리 물어보는 비용은 작지만, 잘못
추측해서 코드를 쓴 뒤에 수정 요청을 받는 비용은 그렇지 않다.

## 적용 대상

앱이 화면에 렌더링하는 **새로운 사용자 노출 문자열**을 추가하거나 수정하는 모든 코드 변경 — 주로
다음과 같은 것들이다:
- input의 `placeholder` 문구
- 필드, 버튼, 탭, 내비게이션 항목의 라벨
- 에러 / 검증 / 빈 상태 메시지
- 토스트, 배너, 알림 문구

다음의 경우에는 적용하지 않는다:
- 내부용 텍스트 (코드 주석, 로그 메시지, 변수명)
- 사용자가 요청 메시지에서 이미 그대로 준 문구 ("체크리스트를 눌러야만 등록되게 해줘"처럼 텍스트가
  이미 정해져 있으면 그대로 사용)
- 이미 명확하고 모호하지 않은 컨벤션이 있어서 사실상 선택지가 하나뿐인, 사소하고 완전히 정해진
  텍스트 (예: 앱 전체에서 `type="submit"` 버튼 문구가 전부 "저장"인 경우 — 형식적으로 보이기 위해
  굳이 질문을 만들어내지 않는다)

## 작업 순서

1. **먼저 기존 컨벤션을 확인한다.** 아무것도 제안하기 전에, 형제 파일/컴포넌트들이 같은 종류의
   문구를 어떻게 쓰고 있는지 살펴본다. 지금 수정하는 파일 근처의 다른 `placeholder=`, 에러 메시지
   맵, 버튼 라벨 등을 grep해본다. 프로젝트는 일부러 스타일을 뒤섞지 않는 경우가 대부분이다 — 이
   앱의 다른 placeholder들이 전부 `"예: ..."` 패턴을 따르거나, 파괴적 동작 버튼이 전부 "제거"가
   아니라 "삭제"라고 되어 있다면, 새 스타일을 만들어내지 말고 제안하는 후보도 그 컨벤션을 따라야
   한다.

2. **AskUserQuestion으로 묻는다 — 서로 다른 문구마다 질문을 하나씩.** 관련 없는 여러 문자열을
   하나의 질문에 몰아넣지 않는다. 사용자가 필드별로 따로 답할 수 있어야 한다. 각 질문에는 다음을
   제시한다:
   - **옵션 A (추천, 먼저 나열):** 1단계에서 확인한 컨벤션을 따르는, 바로 쓸 수 있는 구체적인
     문구. "적절한 예시" 같은 모호한 자리표시자를 내놓지 말고, 실제 후보 문자열 하나를 확정해서
     제시한다.
   - **옵션 B:** 더 무난하고 일반적인 대안 — 사용자가 더 밋밋한 걸 원하거나, 옵션 A의 도메인
     특화 추측이 빗나갔을 경우를 대비한다.
   - AskUserQuestion에는 기본적으로 "직접 입력" 선택지가 있어서 사용자가 정확한 문구를 직접
     타이핑할 수 있으므로, 이를 위한 세 번째 옵션을 따로 추가할 필요는 없다.

   질문은 문구 자체로만 범위를 좁힌다 — 구현 방식에 대한 질문("모달로 할까요, 인라인 에러로
   할까요?")은 그것도 정말 아직 정해지지 않은 경우가 아니라면 섞지 않는다.

3. **답변을 받은 후에만 코드에 문구를 쓴다.** 사용자가 고르거나 직접 준 문구를 구현에 그대로
   사용한다.

4. **사용자가 이미 지시한 문구는 다시 묻지 않는다.** 메시지에 "버튼 이름은 '전송하기'로 해줘"라고
   이미 적혀 있었다면 그건 이미 확정된 것이므로 바로 구현한다.

## 예시

사용자가 현재 placeholder가 없는 "담당자 메모" 입력란에 예시 문구를 추가해달라고 요청한 상황.
같은 폼의 형제 input들은 이미 `placeholder="예: ..."` 형식으로 구체적인 상황을 예시로 쓰고 있다.
코드를 수정하기 전에:

- (AskUserQuestion으로 질문) "'담당자 메모' 입력란에 넣을 예시 문구를 무엇으로 할까요?"
  - 옵션 1 (추천): `예: 고객 견적 요청 접수, 내부 검토 중` — 형제 필드들에서 보이는 기존
    "예: ..." 컨벤션과 일치.
  - 옵션 2: `메모를 입력하세요` — 상황을 지어내지 않는 단순 안내 문구.

이후 사용자가 고른(또는 직접 입력한) 문구로 구현한다.
